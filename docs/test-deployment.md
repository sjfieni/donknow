# 테스트 서버 열기

코드는 https://github.com/sjfieni/donknow 에 저장되어 있습니다.

## Render에서 시작

[Render 배포 설정 열기](https://render.com/deploy?repo=https://github.com/sjfieni/donknow)

1. Render 계정을 만들거나 로그인하고 GitHub 저장소 접근을 허용합니다.
2. 배포할 브랜치는 `main`을 선택합니다. 저장소의 `render.yaml`을 사용합니다.
3. **유료 Starter 서버와 1GB 영구 디스크를 생성하는 설정입니다. 표시되는 서버·디스크 비용을 확인한 다음 배포하세요.** 여기서는 유료 서버를 생성하지 않았습니다.
4. 배포가 완료되면 Render가 발급한 `https://…onrender.com` 주소를 엽니다. 별도 도메인은 필요하지 않습니다.
5. 회원가입 후 테스트용 할 일을 추가하고, 브라우저를 새로고침해 데이터가 유지되는지 확인합니다.

Docker 이미지가 앱과 웹 화면을 함께 제공합니다. Render의 `RENDER_EXTERNAL_URL`을 시작 시 `PUBLIC_ORIGIN`으로 사용하므로 브라우저는 같은 주소의 API에 연결합니다. 데이터베이스와 암호화 키는 `/var/lib/duckduck` 영구 디스크에 유지합니다. GitHub에 새 커밋을 올려도 자동 재배포하지 않도록 설정했습니다.

## 첫 확인

- `/api/health`가 정상 응답하고, 앱에서 클라우드 계정으로 가입/로그인되는지 확인합니다.
- 할 일 추가 → 새로고침 → 완료 → 약 4초 후 log 이동 → 되돌리기를 확인합니다.
- 덕에서 초안을 만들고 Todo에 추가한 뒤 기록 찾기로 검색합니다.
- Render의 수동 재배포 후에도 기존 계정과 할 일이 유지되는지 확인합니다.
- 내정보에서 첫 백업 완료 여부를 확인합니다. 백업 경로는 `/var/lib/duckduck/backups`이고 주기는 24시간, 보관 기간은 14일입니다.

이 백업은 데이터베이스와 같은 디스크에 있습니다. 서버/디스크 자체가 사라지는 상황에 대비한 외부 백업은 S3 등 별도 저장소 연결이 필요합니다. 디스크를 삭제하거나 새 디스크로 바꾸기 전에는 백업과 원래 암호화 키를 보관해야 합니다.

## 나중에 연결할 항목

이메일·OAuth 비밀키는 Render 환경 설정에 등록합니다. GitHub나 채팅에 넣지 않습니다. 이메일 발송 설정 전에는 인증메일/비밀번호 재설정 메일이 전송되지 않습니다. Google 등 외부 서비스는 설정과 이메일 인증을 마친 뒤 연결할 수 있습니다. 필요한 변수와 콜백 경로는 [운영 안내](operations.md)를 참고하세요.

AI 연결과 아이폰 배포는 포함하지 않습니다. 실제 Render 생성/공개 주소 접속은 Render 계정에서 배포한 뒤 검증해야 합니다. 환경에서 수행한 Docker 실행·계정 저장·재시작·백업 복원 검증과 별개입니다.
